# Backend open engineering debt — Reference

Open engineering debt that has no subsystem reference of its own. Every item below was checked against the current code; an item that is fixed or no longer true is deleted rather than annotated. Deliberate design decisions live in [docs/security-posture.md](../../docs/security-posture.md), open security findings in [security-open-items.md](security-open-items.md) — do not duplicate either here.

Each row names the symbol, package or table it is about, so it can be re-checked by reading that code rather than by trusting this page.

## Open

| Where | Open | Why it matters | Suggested direction |
| --- | --- | --- | --- |
| `store.GetPolicy` | A single-row read is still wrapped in a read-write transaction (`BeginTx` + `Commit`); the other single-statement readers now run on the pool. | Two extra round trips and a transaction for no consistency benefit on a pure read path. | Run it on the pool like the other getters; keep a transaction only where more than one statement must share a snapshot. |
| `store.GetInstance`, `store.GetPolicy`, `store.ListSublevelMetaRegistryResource`; `store.ListColumnLineage`, `store.ListOpenLineageRun`, `store.ListOpenLineageTask`, `store.ListExternalDataset`, `store.ListNamespaceMapping`, `store.ListLLMProfiles` | Getters overwrite fields on the caller's `Find*Message` (`ShowDeleted`, `ShowAll`, `LimitPreObjectType`); six `List*` readers dereference a nil `find` with no guard, while two others handle it explicitly (`store.ListManualSQL` defaults it, `store.ListNotifications` rejects it). | A caller that reuses one filter has its query silently changed; a nil filter panics. | Copy the filter into a local or take explicit options; give the six readers one nil policy (reject or empty filter). |
| `store.ManualSQLMessage.ManualSQLID`, `store.FindManualSQLMessage`; `openlineage_api_key` | `ManualSQLID` has no column behind it (`manual_sql` stores `name`), so the read path backfills it; an OpenLineage API key has `revoked_at` but no `expires_at`, and no field for one in the store message. | The resource name has two sources of truth; a key can only be revoked by hand. | Remove the field or add the column; add an expiry column with an incremental migration and the matching `LATEST.sql` change. |
| `store.buildDeleteColumnLineageByGUIDStatement` (manual SQL delete, subtree condition) vs `store.DeleteColumnLineageByMetaGUIDs` (schema sync, type-filtered, batched `= ANY`; caller `runner/schemasync.SyncDatabaseSchema`) | Lineage deletion has two SQL implementations that evolve separately; the runner-side one is batched and type-filtered, the manual-SQL one is not. | Escape and subtree semantics can drift: delete too little or too much. | Merge them into one helper with source/target direction parameters. |
| `store.ListInstances` + `store.hasHostPortFilter`, coupled to `api/v1/filter.go` | Whether the instance list joins data sources is decided by substring-matching the generated SQL for `ds ->> 'host'` / `ds ->> 'port'`. | Renaming a filter column silently drops the join (values are parameterized, so the user cannot inject it). | Have the filter translator return a structured marker such as `NeedsDataSourcesJoin`. |
| `backend/api/auth.GetTokenDuration` | The function ignores its `ctx` and store arguments and always returns the seven-day constant; six call sites pass them anyway, the `token_duration` setting is reserved in the store proto, and a comment still promises a future setting. | Dead parameters plus a misleading future comment. | Remove the parameters and keep the constant, or wire a real configurable setting. |
| `backend/plugin/sqlsanitize` (literal rewrite), `backend/plugin/lineage/doris` (analyzer), application SQL ingest gate | The literal rewrite is position-blind: structural integers become `?`, so `VARCHAR(50)` and `TABLESAMPLE(10 PERCENT)` stop parsing in Doris, which requires integers there and rejects the statement at ingest even though the analyzer can read the original. The rewritten output is identical across MySQL, PostgreSQL, StarRocks, Doris and MSSQL, so this is dialect-neutral, not a Doris defect. | Doris table-creation and sampling statements cannot be ingested as application SQL. Registering Doris narrowed the gate from rejecting every Doris statement to rejecting only these shapes. | Make literal classification position-aware (a cross-dialect change); until then the sanitizer corpus has no `doris` entry. |
| `openlineage_run_dataset.column_lineage_fields` | The column is written during ingestion (at most 32 KiB per output reference) but has no reader: the dataset detail derives its field-level readiness from `store.ListColumnLineageColumnsByGUID`. | Write amplification, and the column can drift from what the page shows. | Drop the column at the next schema change; until then keep writing it for possible reuse but never read page facts from it. |
| `oauth_refresh_token`, `store.DeleteOAuthClient` | `client_id` is `TEXT NOT NULL` with no foreign key to `oauth_client(client_id)`; the delete path exists in the store but has no caller. | Once a registration can be deleted, authorization rows are orphaned; the list already falls back to `client_id` when the join misses. | Add the foreign key or a cascading delete before wiring any delete entry point. |
| `api/v1.ConnectedAppService.RevokeConnectedApp` | After committing the revocation it reloads the snapshot; if maintenance prunes the row by `expires_at` between the two reads, a successful revocation answers `NotFound`. | A rare wrong status code; the revocation itself is already in effect. | Do it in one `UPDATE ... RETURNING`, or accept a miss and return the pre-revocation snapshot. |
| `store.IsOAuthGrantLive` (database `NOW()`), `api/auth` token expiry (Go clock) | Grant liveness compares against the database clock while access-token expiry is computed in Go; a fast database clock rejects tokens early. | Sub-second in practice, but the two clocks can disagree under skew. | Pass `now` into the liveness check, or tolerate the skew in one place. |
| `backend/component/dataquality` capability matrix, `backend/test/integration/env` | MSSQL, StarRocks, Doris (and MariaDB, TiDB, OceanBase) capabilities are pinned only by `capabilities_test.go` and manual container probes; the integration environment starts MySQL and PostgreSQL only, and the nightly matrix varies those two (MySQL 8.0/8.4, PostgreSQL 16/17) but starts no container for the rest. | Real rule and profile execution on those engines is not regression-tested, and engine-version differences can drift. | Add those engines to CI and cover at least profiling and the save-time rejection of unsupported rules; until then a capability change must update the matrix test. |
| `backend/test/integration/runner` quality-directory tests | The package shares one workspace, so a test that asserts on a workspace-wide listing (the target directory's count and its search hits) also sees the targets other tests created; under `-shuffle=on`, `TestDataQualityTargetDirectoryRealServerIntegration` fails on another test's `orders` target. | The suite is only reliable in its fixed order, so CI cannot shuffle it, and a new listing test inherits the same trap. | Scope the assertions to the test's own instance ids, or give the harness a workspace per test, then add a shuffle leg to the nightly. |
| `backend/component/dataquality.executeCELRule` (`celColumns`), `ResolvedTarget.KeyColumns` | Column checks put primary-key columns in the failure sample; a CEL rule's sample carries only the columns the expression references, so several violating rows on one column are distinguishable only by their order. | The sample cannot identify the offending row, and its shape differs from the other rule types. | Select the key columns for storage while evaluating only the referenced ones, or document the gap. |
| `backend/plugin/db/starrocks` sync, `dataquality.primaryKeyColumns` | The StarRocks/Doris driver never fills `TableMetadata.Indexes` (a TODO), so `primaryKeyColumns` returns nil: failure samples lack key columns, and the structure fingerprint on those engines has no primary-key part, which also hides primary-key changes from `schema_drift`. | New checks on those engines miss primary-key changes and cannot identify sampled rows. | Sync the primary index from `SHOW CREATE` or the engine catalog and verify it per version, or record "no index metadata" in the engine capability matrix. |
| `api/v1.AuthService.Logout`, `mcp.Server.auditToolCall` | An MCP token's `Logout` revokes every grant that client holds for the user, but the audited request and response are empty; MCP tool-call audit rows name the actor only, with no client or grant. | After the grant rows are pruned, the permanent ledger cannot say which connection an action belonged to. | Record the revoked client and grant ids in the logout's audit detail; add client/grant fields to tool-call audit rows (mind redaction and row width). |
| `backend/api/v1` group and role handlers, `store` OpenLineage run / namespace mapping / external dataset / LLM profile readers | These files still have no direct test file. The packages that used to have none (`bin/server/cmd`, `component/dbfactory`, `runner/maintenance`) now have one, so the gap is file-level, not package-level. | A regression in these handlers or readers is caught only through broader integration paths, or not at all. | Add file-level tests where a mutation would otherwise pass unnoticed, rather than chasing a package-percentage target. |

## Deliberately kept (do not reopen)

| Item | Why it stays | Where the reason lives |
| --- | --- | --- |
| Connection-test errors carry the driver's cause | Testing a connection requires instance or data-source write permission, and the caller supplied host, port and credentials, so the resolved address is not a secret from them; collapsing the error to `invalid datasource <type>` would leave the action with nothing to report. | Comment on `dataSourceConnectionError` in `backend/api/v1`. |
| The store layer does not validate data sources | Validation stays in the API layer (`InstanceService.checkInstanceDataSources`); `runner/schemasync.SyncInstance` calls `store.UpdateInstance` with stored metadata, so a store-level rule would strand instances whose rows predate it and fail their sync forever. | This page and the sync path. |
| Runner intervals and bounds are compile-time constants | Cadences, batch sizes and timeouts in `runner/schemasync`, `runner/lineageanalyzer`, `runner/maintenance` and `runner/lineagevalidation` are constants with no operator override; making them configurable is a product decision first. | This page. |
| The accepted decisions reviewed alongside these items | Workspace-scoped single-tenant authorization, anonymous gRPC reflection, the same-database data key for credentials, log-only destructive schema sync, permanent audit rows and the reverse-proxy contract are recorded, with their costs, in [docs/security-posture.md](../../docs/security-posture.md). | `docs/security-posture.md` |
